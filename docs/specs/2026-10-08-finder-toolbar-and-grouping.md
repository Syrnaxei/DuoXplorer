# Spec: Finder 风格右上角功能区（分组方式 / 分享 / 编辑标签 / ••• 菜单）

日期：2026-10-08
状态：已对齐（grill-with-docs 共识确认）
术语：见 [CONTEXT.md](../../CONTEXT.md)

## 1. 问题陈述

当前应用顶栏右上角只有一个搜索框，缺少 Finder 的核心操作入口：无法按维度分组浏览目录、无法唤起系统分享、无法给文件打颜色标签、没有鼠标党常用的「菜单按钮」。列表只有平铺的 4 种列头排序，目录内容一多就难以定位。本次变更把右上角改造成 Finder 同款功能区，并引入**真分组**作为列表的一级视图状态。

## 2. 方案概述

- `MainContentView` 工具栏右侧新增 4 个条目（从左到右）：**分组方式 ▾**、**分享**、**编辑标签**、**•••**，现有 `.searchable` 搜索框保持最右不变。
- 新增纯函数接缝 `GroupingService`：输入 `[FileItem]` + 分组维度 + 组内排序（`SortOption`/`SortDirection`），输出有序的 `[(组名, [FileItem])]`。10 个维度的归类、大小/日期分桶、组间排序全部在这个接缝内实现，不触碰 AppKit。
- `FileListView` 的 NSTableView 行模型从「纯文件行」扩展为「文件行 + 分组标题行」；分组标题行不可选中、不可右键。
- `FileItem` 补充分组所需资源属性（创建日期、添加日期、上次打开日期、标签名），沿用现有 `resourceValues` 懒取模式。
- 所有菜单用 `NSMenu`，分享用 `NSSharingServicePicker`，打标签用 `URL.setResourceValue(_:forKey: .tagNamesKey)` —— 零自绘、零新依赖。

## 3. 用户故事

### 分组方式

1. 点击分组方式按钮弹出下拉菜单，10 项按 Finder 图二顺序排列：无 / 名称 / 种类 / 应用程序 / 上次打开日期 / 添加日期 / 修改日期 / 创建日期 / 大小 / 标签；当前维度带 ✓ 勾选态。
2. 选择「无」：列表回到平铺（现有行为），列头排序即全局排序。
3. 选择任一分组维度：列表按该维度分节，每节顶部有一行**分组标题**（组名 + 项目数），标题行不参与选中、右键、重命名、拖拽。
4. 分组激活时点击列头：只改变**组内排序**的维度与方向，分节结构不变。
5. 名称分组：按名称首字符归组（字母归到对应字母，非字母首字符归「#」），组间按字母序。
6. 种类分组：按文件类型大类（文件夹 / 应用程序 / 图像 / 文稿 / 归档 等），组间按组名排序。
7. 应用程序分组：分为「应用程序」与「其他」两组。
8. 日期类分组（上次打开/添加/修改/创建）：按 Finder 惯例分桶——今天 / 昨天 / 前 7 天 / 前 30 天 / 今年 / 更早；属性缺失的条目归「无日期」组。组间按时间从新到旧。
9. 大小分组：文件夹归「文件夹」组（大小无意义），文件按桶从大到小——1 GB 以上 / 100–1000 MB / 10–100 MB / 1–10 MB / 100 KB–1 MB / 10–100 KB / 小于 10 KB；大小未知归「未知大小」。
10. 标签分组：按条目第一个标签归组（组间按 `FinderTag.all` 顺序），无标签条目归「无标签」组。
11. 分组仅作用于目录列表：搜索结果与标签模式下列表保持平铺，分组按钮在两种模式下仍可点但无效果（或置灰，实现取简）。

### 分享

12. 未选中任何对象时分享按钮置灰。
13. 选中 ≥1 个对象时点击分享按钮：弹出 `NSSharingServicePicker`（含隔空投送、邮件、信息等系统服务），分享内容为全部选中对象的文件 URL。

### 编辑标签

14. 未选中任何对象时标签按钮置灰。
15. 选中后点击标签按钮：弹出菜单列出 7 个系统颜色标签（`FinderTag.all`），条目左侧显示色点；**所有选中对象共同拥有**的标签带 ✓。
16. 点击某标签：对所有选中对象应用或移除该标签（toggle），通过 `setResourceValue(_:forKey: .tagNamesKey)` 写入并触发列表刷新；已分组的列表按新标签重新归组。

### ••• 菜单按钮

17. 点击 ••• 按钮在按钮下方弹出与右键完全一致的 NSMenu，复用现有 `menuItems(for:)`：
    - 无选中 → 空白区菜单（新建文件夹 / 粘贴 / 在终端中打开 / 在 Finder 中打开 / 显示隐藏项目，并新增「分组方式」子菜单，内容同故事 1）；
    - 有选中 → 选中对象菜单（打开 / 复制 / 剪切 / 重命名 / 在 Finder 中显示 / 复制路径 / 移到废纸篓）。

### 搜索

18. 搜索框保持现状（`.searchable`，Spotlight 递归搜索），本次不改。

## 4. 已定决策

- **真分组**：分节 + 标题行，不是把菜单映射到现有排序（拷问确认，弃掉「只改排序」方案）。
- 分组维度**全部 10 项**，不裁剪。
- 列头与分组的关系：**列头管组内排序**，不退出分组、不禁用列头。
- 分组**仅目录列表生效**，搜索/标签结果平铺。
- 分组状态为会话级 `@State`（与现有 `sortOption` 一致），**不持久化**——应用无 UserDefaults，维持零用户状态。
- 四个按钮均为原生接口/原生图标：SF Symbols 图标 + NSMenu + NSSharingServicePicker + tagNames resource value。
- 空白区右键菜单补充「分组方式」子菜单。

## 5. 测试决策

- **主接缝**：`GroupingService.group(files:by:sort:direction:)` 纯函数。10 个维度的归类与分桶全部在此测试，用一个断言式自检文件覆盖（构造临时文件 URL + 注入资源属性，断言各组名称、顺序、成员归属；大小/日期桶用预造 Date/ByteCount 验证边界）。ponytail 规则：一个可运行 check，无框架。
- **次接缝**：NSTableView 行模型（文件行/标题行）映射——分组开、关两个状态下选中索引 ↔ URL 的映射断言。
- UI 层（按钮出现顺序、置灰、勾选态、菜单弹出位置）按惯例由用户手动验证；交付时给出 `./build_and_run.sh` + 逐条验证清单（预期现象）。

## 6. 明确不做

- 自定义（非 7 色系统）标签的创建与管理。
- 分组/排序状态的持久化与恢复。
- 搜索结果、标签模式的分组渲染。
- Finder 的其他视图模式（图标/分栏/画廊）与「显示选项」⌘J。
- 「使用始终……」类分组记忆（Finder 分组菜单里的永久生效项）。
- 分组标题行的折叠/展开。

## 7. 补充说明

- 图二菜单中的 `--` 快捷键列（如「名称 ⌃⌘0」等）是 Finder 的系统快捷键位，本次不占用这些快捷键，菜单不设 keyEquivalent，避免与现有快捷键冲突。
- 「上次打开日期」取 `contentAccessDate`（及 `kMDItemLastUsedDate` 回退），部分文件系统不记录访问时间，缺失即归「无日期」。
- 建议随实现记录一条 ADR（`docs/adr/`）：真分组取代平铺排序成为列表一级视图状态、列头语义随之从「全局排序」变为「组内排序」——理由与备选（映射排序）已在拷问中排除。
- 涉及文件（预估）：`MainContentView.swift`（工具栏）、`FileListView.swift`（行模型/菜单）、新 `GroupingService`、新分组维度枚举、`FileItem.swift`（补属性）、`FileSystemService.swift`（写标签）。
